01 — Unwrap

The number you were given is not the error

Message 50000 means user code re-raised something. Error 3041 is a summary logged after the failure.

The real error sits immediately above the 3041

Find the 3041, note its timestamp, then read the entries just before it. The specific failure is almost always within a line or two.

Two search strings AND together, which narrows fast: EXEC xp_readerrorlog 0, 1, N'BACKUP', N'YourDB';

If a third-party tool drives the backup

Look for SQLVDI: lines near the failure. Their presence means the detail genuinely lives in the vendor's log — Veeam, Commvault, NetBackup, Rubrik, LiteSpeed — not in SQL Server. A common trap there: log backups on a secondary cannot be COPY_ONLY, but many tools issue copy-only by default.

02 — Archives

Reading ERRORLOG.N

Archived logs are plain text despite having no extension. Current is ERRORLOG, previous is ERRORLOG.1, and the count rolls on every service restart or sp_cycle_errorlog.

In SSMS: Object Explorer → Management → SQL Server Logs. Log File Viewer can load several archives at once, so you can search across them rather than one at a time.

On disk, do not guess the path — ask the instance:

C:\Program Files\Microsoft SQL Server\MSSQL##.INSTANCE\MSSQL\Log\

Files are UTF-16LE. Garbled text or interleaved nulls means the reader picked the wrong encoding, not a corrupt file.

03 — Extended events

AlwaysOn_health

Binary .xel files — not readable in a text editor. This session records role changes, lease timeouts, suspend and resume, and AG DDL, and it reaches back much further than the error log.

In SSMS: Management → Extended Events → Sessions → AlwaysOn_health → right-click the target → View Target Data. Or File → Open → File on the .xel itself, which pulls in the whole rollover set from that folder.

The wildcard in the path matters — it reads every rollover file in one pass. Timestamps come back in UTC; convert before comparing against the error log.

If SELECT name FROM sys.dm_xe_sessions; does not list AlwaysOn_health, the session is stopped and there is nothing to read. It is created by the AG wizard but not always left running.

04 — Cluster

Windows failover cluster logs

The detailed cluster log does not exist as a file until you generate it. Everything else lives in Event Viewer.

Without -Destination it writes to C:\Windows\Cluster\Reports\ on each node. It pulls from all nodes by default — add -Node NODE01 to narrow. Always pass -UseLocalTime, or timestamps arrive in UTC and will not line up with the SQL error log. Search the output for [RES], ERR, and the AG's resource name.

Event Viewer → Applications and Services Logs → Microsoft → Windows → FailoverClustering

Also check the Windows System log for cluster service start and stop events — those often explain a transient disconnect better than the cluster log does.

05 — Job layer

What the Agent recorded

When a maintenance script masks the error as 50000, its own logging usually kept the original number.

Empty or stale means the job was not run with @LogToTable = 'Y'.

A scope of USER_DATABASES will happily attempt log backups on databases that are not AG members — a frequent explanation for a handful of failures among many successes.
